## 1. КАК ЗАПУСТИТЬ ПРОЕКТ

### Вариант А. Portable-запуск на Windows (без прав админа) — РЕКОМЕНДУЕТСЯ

В папке `StudentPerformanceApi/publish/` находится готовая сборка. Ничего устанавливать не нужно.

**Шаг 1:** Скопируй папку `publish` на флешку и перенеси на учебный компьютер.

**Шаг 2:** Открой папку `publish` и запусти файл **`start.bat`** (двойной клик).

**Шаг 3:** Открой браузер и перейди по адресу:
```
http://localhost:5002
```

**Что произойдёт:**
- Автоматически запустится сервер API
- Создастся файл базы данных `StudentPerformance.db` рядом с программой
- В браузере откроется готовое приложение (клиент встроен в сервер)
- Swagger доступен по адресу: `http://localhost:5002/swagger`

> 💡 Если нужна чистая база — просто удали файл `StudentPerformance.db` перед запуском, и он создастся заново с тестовыми данными.

## 3. АРХИТЕКТУРА И КОД (если препод попросит показать код)

### Структура серверной части
Показать папки в `StudentPerformanceApi/`:
- `Models/` — сущности БД (Group, Student, Teacher, Subject, Grade)
- `DTOs/` — модели передачи данных (разделение запросов и ответов)
- `Data/` — ApplicationDbContext (Code First)
- `Repositories/` — паттерн Repository (Generic + Specific)
- `Services/` — бизнес-логика (инкапсуляция правил)
- `Controllers/` — REST API (CRUD + специальные эндпоинты)
- `Auth/` — JWT-сервис

**Ключевая фраза:**
> "Применен паттерн Repository + Service Layer. Контроллеры не обращаются к БД напрямую, а делегируют работу сервисам, а те — репозиториям. Это обеспечивает разделение ответственности и тестируемость."

## 5. ВОЗМОЖНЫЕ ВОПРОСЫ ПРЕПОДАВАТЕЛЯ И ОТВЕТЫ

**В: Почему выбран React, а не Angular/Vue?**
**О:** Низкая кривая обучения, виртуальный DOM для высокой производительности, огромная экосистема библиотек. Для учебного проекта — оптимальный выбор.

**В: Почему SQLite, а не MS SQL Server / PostgreSQL?**
**О:** SQLite — встраиваемая база данных, не требует установки сервера. Для демонстрации учебного проекта это удобно: база — просто файл, переносится вместе с программой. При необходимости легко мигрировать на PostgreSQL или MS SQL.

**В: Что такое Code First?**
**О:** Подход Entity Framework, при котором схема БД создается на основе C# классов-моделей. Миграции позволяют версионировать изменения структуры БД.

**В: Зачем DTO-модели?**
**О:** Для разграничения внутренних сущностей БД и данных API. DTO обеспечивают безопасность (исключают циклические ссылки), гибкость (разный набор полей для разных операций) и оптимизацию (не тянем лишние данные).

**В: Как работает JWT?**
**О:** При входе сервер генерирует токен с claims (email, роль). Токен подписан секретным ключом. Клиент передает его в заголовке Authorization. Middleware проверяет подпись и срок действия.

**В: Что такое Dependency Injection?**
**О:** Паттерн, при котором зависимости (сервисы, репозитории) внедряются в классы через конструктор, а не создаются внутри. Это снижает связанность компонентов и упрощает тестирование.

**В: Почему Repository + Service, а не напрямую из контроллера?**
**О:** Разделение ответственности. Контроллер — HTTP, Service — бизнес-логика, Repository — доступ к данным. Можно заменить БД или фреймворк без изменения контроллеров.

**В: Какие роли реализованы?**
**О:** Admin (полный CRUD), Teacher (чтение + добавление оценок), Student (только просмотр собственной успеваемости).

**В: Как реализована связь многие-ко-многим?**
**О:** Через ассоциативную сущность Grade. Студент и Предмет связаны через Grade (StudentId + SubjectId).
